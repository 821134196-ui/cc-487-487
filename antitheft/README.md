# 服装门店防盗扣领用与漏拆复核系统

覆盖门店、扣具类型、库存、楼层领用、商品挂扣批次、收银拆扣回收、回收盒、
闭店清点、出口报警复核、消磁器故障、扣具报损与盘差审批的完整闭环。
**零第三方依赖**，仅需 Python 3.9+（标准库 sqlite3 / http.server）。

## 一条本地启动命令

```bash
cd antitheft
./run.sh              # 导入漏拆/串台/盘差样例并启动，含进程内闭店与提醒任务
# 打开 http://localhost:8621   （端口可用 PORT=9000 ./run.sh 覆盖）
```

单独导入样例：`python3 -m app.seed data/antitheft.db evidence`
仅启动（不重置数据）：`python3 -m app.web --db data/antitheft.db --evidence evidence`

## 角色与职责分离

| 角色 | 权限 |
|---|---|
| 导购 ASSOCIATE | 楼层领用、商品挂扣、扣具报损、发起盘差 |
| 收银 CASHIER | 收银拆扣回收、消磁故障上报、出口报警复核 |
| 店长 MANAGER | 盘差审批、消磁器恢复（不参与领用/拆扣） |

页面右上角可切换当前身份；越权操作会被服务层拒绝并提示。

## 核心业务规则

- **数量守恒**：每次变动写两行数量流水（借贷共享 `move_id`），
  总仓→楼层散扣→在架商品→回收盒，报损与盘差调整也在同一张窄表内守恒。
- **闭店平衡数量链**：`领用 ＝ 挂扣＋楼层散扣＋散扣报损＋盘差调出`；
  `挂扣 ＝ 拆回＋在架＋在架报损＋盘差调出`。页面用一条横向数量链展示。
- **同一交易拆扣只确认一次**：`detach_events` 对 POS 来源的 `txn_id` 建唯一索引；
  报警二次复核、盘差二次审批同样被拦截。
- **并发乐观锁**：库存窄表带 `version`，两人并发调整时后提交者收到版本冲突，绝不超扣。
- **异常分别处理**：
  - 扣型不匹配 → 登记 MISMATCH 批次，不动库存；
  - 领用短缺 → 按总仓实发，记 ISSUE_SHORT；
  - 回收盒串台 → 扫描到他台盒子整笔拦截，交易不成立；
  - 消磁失败 → 消磁器置故障，交易自动转 MANUAL 手工拆扣；
  - 无交易报警 → 不允许按漏拆回收，只能升级防损/店长；
  - 扣具破损 → FLOOR/ONGOODS 转 DAMAGED；
  - 盘点差异 → 导购申请、店长批准，经 ADJUST 过渡调账。
- **出口报警复核**：页面优先展示**收银时间线与扣型类型**（成交→售出→拆扣→漏拆→报警），
  确认漏拆后回收到本台回收盒并关闭事件；白底洋红强调，不用整屏红色。

## 样例场景（启动即有）

- E1001 正常消磁拆扣；E1002 消磁器故障手工拆；
- E1003 漏拆 1 个硬扣 → 18:35 东门报警（关联交易，待收银复核）；
- E1004 回收盒串台被拦截，E1005 纠正后成交；
- 无交易西门报警（待升级）；F2 钢丝绳扣领用短缺；连衣裙错领扣型不匹配；
- F1 硬扣散扣盘亏 1（导购已立盘差单，待店长批准）。

## 数据与产物

- `data/antitheft.db`：SQLite，库存为「门店×扣型×位置×楼层/盒子」**窄表**，
  全部数量变动入 `inventory_ledger` 流水。
- `evidence/*.svg`：门禁适配器模拟抓拍的报警凭证。
- 进程内守护线程按闭店点生成 `close_counts`，并把待批盘差/待复核报警/未恢复故障
  写入 `task_runs` 差异提醒。
