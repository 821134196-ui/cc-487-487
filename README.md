# 服装门店防盗扣领用与漏拆复核系统

管理门店防盗扣的**入库 → 楼层领用 → 商品挂扣批次 → 收银拆扣回收 → 出口报警漏拆复核 →
扣具报损 → 闭店清点平衡 → 盘差审批**全链路。零第三方依赖，仅用 Python 标准库
（`http.server` + `sqlite3`），SQLite 保存数量流水，本地目录存放门禁报警凭证，
进程内守护线程生成闭店清点与差异提醒，模拟适配器返回收银交易与门禁报警。

## 一条命令启动（导入漏拆 / 串台 / 盘差样例）

```bash
python3 -m tagguard.app --demo
```

打开 http://localhost:8000 。`--demo` 会重置并导入样例数据（门店、扣型、商品、
成交交易），自动执行一次带盘差的闭店清点，并启动进程内巡检任务。

其他参数：

```bash
python3 -m tagguard.app                    # 默认 data/tagguard.db，空库自动导样例
python3 -m tagguard.app --port 8080
python3 -m tagguard.app --db /tmp/t.db     # 凭证默认落在 /tmp/evidence
python3 -m tagguard.app --reset            # 重置后重新导样例
python3 -m tagguard.app --no-scheduler     # 不启动后台巡检/闭店线程
```

运行数据：SQLite 库文件 + `evidence/` 报警凭证目录（默认与库同目录）。

## 样例场景

| 场景 | 样例内容 | 处理入口 |
|---|---|---|
| 漏拆 | 1F 丝巾成交时消磁失败，扣未拆，顾客出门触发东门报警 | 出口报警 → #1 → 收银时间线复核，确认漏拆后回收并关闭 |
| 回收盒串台 | 2F 衬衫在 2F-01 台拆扣 2 枚，误投 2F-02 号盒 | 收银回收 → 串台事件 #1 → 调正回盒 |
| 盘差 | 闭店实盘 1F 墨黑硬扣比期望少 2 枚 | 闭店平衡显示差异 → 盘差审批，仅店长可批准 |
| 扣型不匹配 | 西裤要求硬扣，临时改用墨水扣 | 挂扣批次须注明改用原因，批次打「改用」标记 |
| 领用短缺 | 仓库不足时登记 `short` 短缺单，不动库存 | 楼层领用列表 |
| 重复拆扣 | 同一交易拆扣唯一（DB UNIQUE 强约束） | 收银流水再次拆扣即拒绝 |
| 消磁失败/设备故障 | 单笔消磁失败拦截拆扣；设备故障登记维修 | 消磁故障页 |
| 无交易报警 | 西门报警匹配不到成交，不能按漏拆回收 | 报警页走安保核查关闭流程 |
| 扣具破损 | 区分在架破损与未挂备用扣破损 | 闭店数量链分别计损 |

## 业务规则

**数量守恒口径**（按 门店 × 楼层 × 扣型 × 营业日）：

- 在架平衡：`挂扣 = 拆回 + 实盘在架 + 在架报损 + 差异`
- 领用平衡：`领用 + 拆回 = 挂扣 + 楼层余存 + 备用扣报损`
- 全店守恒：`入库 = 各位置库存 + 在架扣具(挂-拆) + 备用扣报损`

每次库存增减写一条不可变 `stock_ledger` 流水（issue/requisition/attach/detach/
damage/adjust），结余连续。库存行带 `version` 乐观锁，两人并发持同一版本调整时，
后提交者抛出版本冲突，不发生覆盖。

**职责分离**：

- 导购 clerk：领用、挂扣、报损
- 收银 cashier：拆扣回收、报警复核、串台调正、故障处理
- 店长 manager：闭店清点、盘差批准（盘盈补入 / 盘亏出账，落 adjust 流水）
- 同一交易的拆扣事件只允许确认一次；同一报警/串台/盘差单不可重复处理

## 进程内任务

`scheduler.py` 守护线程（无需 cron）：

- 每日 21:50（可配）自动生成闭店清点，不平衡行自动开盘差待审批单并发提醒；
- 每 60 秒巡检：未复核报警、未调正串台、未处理故障、待批盘差，提醒幂等。

页面右上角可切换当前操作身份以体验权限控制（演示用途）。

## 页面

门店白底、雅黑字体、醒目洋红（`#d41472`）点缀：

- **扣具库存**：楼层 × 扣型窄表，带数量与版本号；
- **闭店平衡**：每行一条 `领用 → 挂扣 → 拆回 → 在架 · 报损` 数量链，附校验式；
- **报警复核**：优先展示收银时间线（成交 → 消磁失败/未拆扣 → 出口报警）与
  扣具类型，状态用小徽章标识，不使用整屏红色。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖（30 个用例）：

- 数量守恒（全店来源=去向、流水结余连续、闭店数量链）
- 重复事件（拆扣/报警/串台/无交易事件唯一确认）
- 并发调整（两线程同版本提交，一成一冲突，版本只 +1）
- 职责分离（导购/收银/店长越权均拒绝）
- 盘差审批（生成、批准调账、驳回不动账、不可重复审批）
- 扣型不匹配、领用短缺、破损计损、适配器凭证、调度器幂等

## 目录结构

```
tagguard/
  db.py         SQLite schema、事务与版本锁
  service.py    领域服务（八类异常分别处理 + 闭店平衡 + 盘差审批）
  adapters.py   模拟 POS 收银 / 门禁报警 / 消磁器适配器
  scheduler.py  进程内闭店清点与巡检提醒线程
  seed.py       样例数据（漏拆/串台/盘差…）
  web.py        页面渲染（窄表、数量链、时间线）
  app.py        HTTP 入口（标准库 http.server）
tests/
  test_system.py      守恒/重复/并发/职责分离/盘差等
  test_scheduler.py   闭店任务与提醒幂等
```
